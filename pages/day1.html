The 'Why' — Conceptual Breakdown

The Manual Tester's Reality

Picture your typical Monday morning. You have a regression test plan with 40 line items: connect to 8 different SSIDs, verify each one gets a valid IP address, check that signal strength is above a threshold, note the association time, open a browser to confirm the internet loads, and then write it all down in an Excel spreadsheet.

By Wednesday you've clicked the same "Connect" button 200 times. Your fingers hurt. You made a typo in row 34. Your manager wants this repeated on three different laptops. You want to quit.

This is not a skills problem. It is a tooling problem.
Repetitive, deterministic work is exactly what computers were designed to do — not the humans sitting in front of them.

The Automation Promise

Now imagine a different Monday. You open your terminal, type one command, and go make coffee. When you return, a clean HTML report is sitting in a folder with: pass/fail status for all 40 test cases, the exact timestamp each connection succeeded or failed, the IP addresses that were assigned, and a log file you can attach directly to your bug report.

That is the promise of WLAN automation. And Python is the key.

Why Python?

Think of Python as the English of programming languages — it reads almost like plain sentences:

Python 
# This almost reads like plain English:
if signal_strength < -75:
    print("Signal too weak — test FAILED")

Python has a massive ecosystem of ready-made libraries for networking, testing, and reporting. It runs on Windows, macOS, and Linux. And most critically — the entire WLAN and networking industry already uses it. Tools like Scapy, pytest, and iPerf3 all speak Python.

Code Walkthrough — Your First WLAN Script

Create a new file called Day01_hello_wlan.py inside your wlan-automation-course/ folder and paste the code below. Read every comment — they explain exactly what each line does.

Block 1 — Imports & Setup

Every Python script starts by importing the libraries it needs. Think of this like gathering your tools before you start work.

Python Day01_hello_wlan.py 
# =============================================================
# Day 1: Hello, WLAN Automation!
# Purpose: Discover all network interfaces on this machine
#          and identify which ones are wireless.
# =============================================================

import netifaces  # Third-party: read network interface names & addresses
import psutil     # Third-party: read system and network I/O stats
import platform   # Built-in:    tells us which OS we're running on
Block 2 — System Info Function

A function is a reusable named block of code. We define it once with def and can call it as many times as we like. This function prints a banner showing which OS and Python version we're running.

Python 
def get_system_info():
    """Print basic system info relevant to WLAN testing."""
    print("=" * 55)
    print("  WLAN AUTOMATION COURSE — Day 1 System Check")
    print("=" * 55)

    # platform.system() returns 'Windows', 'Linux', or 'Darwin' (macOS)
    os_name = platform.system()
    print(f"  Operating System : {os_name} {platform.release()}")
    print(f"  Python Version   : {platform.python_version()}")
    print("=" * 55)
Block 3 — Network Interface Discovery

This is the core of Day 1. We ask the OS to list every network interface, then read each one's IP address and MAC address. netifaces.interfaces() is like running ipconfig or ifconfig but from inside Python — and the result is a clean Python list we can loop over.

Python 
def list_network_interfaces():
    """
    Discover and display all network interfaces.

    netifaces.interfaces() returns a list like:
      Linux   → ['lo', 'eth0', 'wlan0']
      Windows → ['Loopback', 'Wi-Fi', 'Ethernet']
    """
    print("\n[+] Discovering Network Interfaces...")
    print("-" * 55)

    # Get every interface name the OS knows about
    interfaces = netifaces.interfaces()

    for iface_name in interfaces:

        # netifaces.ifaddresses() returns a dict of address families:
        #   AF_INET  (value 2)     = IPv4 addresses
        #   AF_LINK  (value 17)    = MAC / hardware addresses
        addresses = netifaces.ifaddresses(iface_name)

        # .get(key, default) is safe — won't crash if key is missing
        ipv4_info = addresses.get(netifaces.AF_INET, [{}])
        ipv4_addr = ipv4_info[0].get('addr', 'No IPv4 assigned')

        mac_info  = addresses.get(netifaces.AF_LINK, [{}])
        mac_addr  = mac_info[0].get('addr',  'No MAC address')

        # Label wireless interfaces for easy reading
        is_wireless = any(tag in iface_name.lower()
                          for tag in ['wlan', 'wi-fi', 'wifi', 'wl', 'airport'])
        label = "[WIRELESS]" if is_wireless else "[WIRED/OTHER]"

        print(f"  {label} {iface_name}")
        print(f"    IPv4 : {ipv4_addr}")
        print(f"    MAC  : {mac_addr}")
        print("-" * 55)
Block 4 — Network I/O Stats

psutil.net_io_counters(pernic=True) returns live byte counters for every interface — the same numbers you'd see in Task Manager or nload. Later in this course we'll use these counters to measure throughput during automated tests.

Python 
def check_network_stats():
    """Show live network I/O counters — a preview of throughput testing."""
    print("\n[+] Network I/O Statistics (Current Snapshot):")
    print("-" * 55)

    # pernic=True → stats broken down per network interface card
    net_stats = psutil.net_io_counters(pernic=True)

    for iface_name, stats in net_stats.items():
        # Convert raw bytes → megabytes for human readability
        sent_mb = stats.bytes_sent / (1024 * 1024)
        recv_mb = stats.bytes_recv / (1024 * 1024)

        # :<20 pads the name to 20 chars (left-align); :>8.2f right-aligns 2 decimals
        print(f"  {iface_name:<20} | Sent: {sent_mb:>8.2f} MB | Recv: {recv_mb:>8.2f} MB")

    print("-" * 55)
Block 5 — Entry Point (Run the Script)

The if __name__ == "__main__": block is a Python convention. It means: "only run this code when the script is executed directly, not when it's imported as a module by another script." Always use this pattern.

Python 
if __name__ == "__main__":
    get_system_info()
    list_network_interfaces()
    check_network_stats()

    print("\n[✓] Day 1 Complete! Your Python environment is ready.")

Hands-on Exercise — Your Turn

The list_network_interfaces() function already labels interfaces as [WIRELESS] or [WIRED/OTHER]. Your challenge is to extend it:

  • Task 1: If an interface is labelled [WIRELESS] and has a valid IPv4 address (not 'No IPv4 assigned'), print an additional line: " ↳ Active wireless connection detected!" in a visually distinct way.
  • Task 2: Count how many wireless and how many wired interfaces are found and print a summary line at the end: "Summary: X wireless, Y wired/other interfaces found."
  • Bonus: Use psutil.net_io_counters(pernic=True) to show bytes received for only the wireless interfaces in the summary.
Hint: Use a counter variable (e.g., wireless_count = 0) before the loop, increment it inside with wireless_count += 1, and print it after the loop ends. The in operator checks if a substring is present: if "No IPv4" not in ipv4_addr.
