Interface State Management —
Context Managers & Safe Mode Switching

What happens when your monitor-mode test crashes halfway through? Your adapter stays in monitor mode, your machine loses Wi-Fi, and your next test run fails silently. Today you'll build a context manager that guarantees interfaces always return to their original state — plus a pre-test checklist that validates your environment before running anything.

The 'Why' — Conceptual Breakdown

The Resource Leak Problem in WLAN Testing

When a test script changes a Wi-Fi interface to monitor mode, it creates a resource obligation: the obligation to restore it when done. If the script crashes, hits a keyboard interrupt, or encounters an exception, the restore code in a plain finally block might not run. More importantly, if 10 different test functions all manage interface state individually, you have 10 places to get it wrong.

Context managers encode "set up and tear down" as a unit.
The with monitor_mode("wlan0") as iface: pattern guarantees that the interface is put into monitor mode on entry and restored on exit — even if the body raises an exception. This is the same pattern Python uses for file handles, database connections, and locks.

The contextlib.contextmanager Decorator

You can turn any generator function into a context manager using @contextlib.contextmanager. Code before the yield runs on entry (__enter__). Code after the yield runs on exit (__exit__), whether the block completed normally or raised an exception. The yield expression is what appears as as iface in the with statement.

Block 1 — get_interface_info()

Before changing anything, always read the current state. This function captures a snapshot of the interface's current mode, IP address, and whether it's up — so you can restore it exactly.

Python Day15_interface_mgmt.py 
# =============================================================
# Day 15: Interface State Management
# =============================================================

import subprocess
import contextlib
import re

def get_interface_info(interface):
    """
    Read current interface state: mode, flags, IPv4 address.
    Returns a dict with all relevant state for later restoration.
    """
    result = subprocess.run(
        ["iw", "dev", interface, "info"],
        capture_output=True, text=True
    )

    info = {"interface": interface, "mode": "managed", "up": False, "ip": None}

    # Extract current mode (managed / monitor / AP)
    m = re.search(r"type (\w+)", result.stdout)
    if m:
        info["mode"] = m.group(1)

    # Check if interface is UP via ip link show
    link_result = subprocess.run(
        ["ip", "link", "show", interface], capture_output=True, text=True
    )
    info["up"] = "UP" in link_result.stdout

    # Get IPv4 address if assigned
    addr_result = subprocess.run(
        ["ip", "-4", "addr", "show", interface], capture_output=True, text=True
    )
    ip_m = re.search(r"inet (\d+\.\d+\.\d+\.\d+)", addr_result.stdout)
    if ip_m:
        info["ip"] = ip_m.group(1)

    return info

info = get_interface_info("wlan0")
print(f"[Interface Info] {info}")
Block 2 — monitor_mode() Context Manager

The @contextlib.contextmanager decorator is the cleanest way to write a context manager without defining a full class with __enter__ and __exit__. The code before yield sets up; the code after yield tears down in a finally block.

Python 
# ── Block 2: monitor_mode() context manager ──────────────────

@contextlib.contextmanager
def monitor_mode(interface="wlan0"):
    """
    Context manager that switches an interface to monitor mode,
    yields the monitor interface name, then restores managed mode.

    Usage:
        with monitor_mode("wlan0") as mon_iface:
            sniff(iface=mon_iface, ...)
        # Interface is automatically restored here
    """
    # ── Setup (runs on 'with' entry) ──────────────────────────
    original_info = get_interface_info(interface)
    print(f"[+] Entering monitor mode on {interface}")

    subprocess.run(["ip", "link", "set", interface, "down"],  check=True)
    subprocess.run(["iw", "dev", interface, "set", "type", "monitor"], check=True)
    subprocess.run(["ip", "link", "set", interface, "up"], check=True)

    mon_iface = interface   # Some drivers rename to wlan0mon — check if needed

    try:
        yield mon_iface   # ← The 'as' variable in the with statement

    finally:
        # ── Teardown (always runs, even on exception) ─────────
        print(f"[+] Restoring {interface} to {original_info['mode']} mode")
        subprocess.run(["ip", "link", "set", interface, "down"], check=True)
        subprocess.run(["iw", "dev", interface, "set", "type",
                         original_info["mode"]], check=True)
        subprocess.run(["ip", "link", "set", interface, "up"], check=True)
        print(f"[✓] {interface} restored")

# Usage example:

Block 3 — check_monitor_support()

Not all Wi-Fi adapters support monitor mode. Attempting to set monitor mode on an unsupported adapter will fail silently or produce unexpected behaviour. This check catches the problem early with a clear error message.

Python 
# ── Block 3: Check monitor mode support ──────────────────────

def check_monitor_support(interface):
    """
    Check if the interface supports monitor mode.
    Uses 'iw phy' to query supported interface types.
    """
    # Get the phy name for this interface
    iw_result = subprocess.run(
        ["iw", "dev", interface, "info"], capture_output=True, text=True
    )
    phy_m = re.search(r"wiphy (\d+)", iw_result.stdout)
    if not phy_m:
        return False, "Could not determine phy number"

    phy = f"phy{phy_m.group(1)}"
    phy_result = subprocess.run(
        ["iw", "phy", phy, "info"], capture_output=True, text=True
    )

    if "monitor" in phy_result.stdout.lower():
        return True, f"{interface} supports monitor mode"
    else:
        return False, f"{interface} does NOT support monitor mode"

ok, msg = check_monitor_support("wlan0")
print(f"[Monitor Support] {msg}")
Block 4 — pre_test_checklist()

A preflight checklist runs before any test that uses the interface, catching problems early. This becomes a pytest fixture in Day 29.

Python 
# ── Block 4: pre_test_checklist() ────────────────────────────

def pre_test_checklist(interface):
    """
    Run all pre-test checks before starting a monitor-mode session.
    Returns True if all checks pass, False otherwise.
    """
    checks = []

    # Check 1: Interface exists
    result = subprocess.run(["ip", "link", "show", interface],
                            capture_output=True, text=True)
    checks.append(("Interface exists", result.returncode == 0))

    # Check 2: Monitor mode supported
    ok, msg = check_monitor_support(interface)
    checks.append(("Monitor mode support", ok))

    # Check 3: Running as root (required for mode switching)
    import os
    checks.append(("Running as root", os.geteuid() == 0))

    # Print results
    print("\n[Pre-Test Checklist]")
    all_ok = True
    for name, passed in checks:
        icon = "✓" if passed else "✗"
        status = "PASS" if passed else "FAIL"
        print(f"  [{icon}] {name:30s} {status}")
        if not passed:
            all_ok = False

    return all_ok

all_ok = pre_test_checklist("wlan0")
print(f"\nChecklist result: {'READY' if all_ok else 'NOT READY'}")

Hands-on Exercise — Your Turn

Harden the interface management module for production use:

  • Task 1: Extend get_interface_info() to also record the current channel (using iw dev <iface> info and parsing the channel field). Restore the original channel after the context manager exits — not just the mode.
  • Task 2: Add a timeout parameter to monitor_mode(): if the test code inside the with block runs longer than the timeout, automatically exit monitor mode and raise a TimeoutError. Use signal.alarm() on Linux.
  • Bonus: Write a save_interface_state(interface, path) function that writes the interface state dict to a JSON file. Add a restore_from_file(path) function for disaster recovery — if your script is killed with SIGKILL (not just SIGTERM), you can run the restore script manually to recover the interface.
Hint: For the timeout pattern use signal.signal(signal.SIGALRM, handler) and signal.alarm(seconds) before the yield in your context manager. Call signal.alarm(0) in the finally block to cancel the alarm on clean exit.
