The 'Why' — Conceptual Breakdown

The Manual Tester's Mental Model

When you test Wi-Fi manually, your brain is constantly storing and comparing information:

"The SSID I need to connect to is CorpNet_5G. The password is Sup3rS3cure!. The expected IP range is 192.168.10.x. Signal strength must be better than -70 dBm."

You're holding values (the actual data) and labels (what those values mean) in your head simultaneously. When something doesn't match, you flag it as a failure.

Python does the exact same thing — except it stores these values in variables, never forgets them, never makes a typo, and can check thousands of them per second.

The Analogy: Variables Are Labelled Boxes

Imagine a set of cardboard boxes on a shelf. Each box has a label on it. You can put something in, take it out, or swap the contents any time you like.

Python 
# Creating labelled boxes and putting values inside them:
ssid      = "CorpNet_5G"   # Box labelled "ssid"    holds text
rssi      = -68            # Box labelled "rssi"    holds a number
connected = True           # Box labelled "connected" holds True/False

Why Data Types Matter in WLAN Testing

Not all Wi-Fi data is the same kind of thing — and Python needs to know the difference so it can work with the data correctly:

  • An SSID is text → str (string)
  • An RSSI value is a whole number → int (integer, always negative)
  • A channel frequency has decimals → float (e.g. 5.18 GHz)
  • A "is dual-band?" flag is yes/no → bool (True or False)
  • A list of channels is multiple values → list
  • A full AP profile is labelled key-value pairs → dict (dictionary)

Choosing the right type isn't academic — it determines what operations you can perform. You can't do maths on an SSID. You can't check if a number "contains" a substring. Types enforce correct thinking.

Block 1 — Strings: For All Text Data

Strings store any text value — SSIDs, passwords, security types, MAC addresses, error messages. They are always wrapped in quotes.

Python Day02_variables_and_data_types.py 
# =============================================================
# Day 2: Variables & Data Types for WLAN Automation
# =============================================================

# --------------------------------------------------
# BLOCK 1: STRINGS — text data
# --------------------------------------------------
ssid          = "CorpNet_5G"
password      = "Sup3rS3cure!"
security_type = "WPA3-SAE"
bssid         = "AA:BB:CC:DD:EE:FF"   # The AP's MAC address

# type() tells you what kind of data is stored in a variable
print(f"SSID: '{ssid}' | Type: {type(ssid)}")
# Output: SSID: 'CorpNet_5G' | Type: <class 'str'>

# Strings have built-in methods — extremely useful for parsing scan output:
print(ssid.upper())            # CORPNET_5G  → case-insensitive comparisons
print(ssid.replace("_", "-"))  # CorpNet-5G  → clean up parsed text
print(len(ssid))               # 10           → 802.11 max SSID length is 32 chars
Block 2 — Integers & Floats: For Numeric Data

RSSI values and channel numbers are integers (whole numbers). Frequencies are floats (they have a decimal point). The critical difference matters when you do maths — and every threshold check is maths.

Python 
# --------------------------------------------------
# BLOCK 2: INTEGERS & FLOATS — numeric data
# --------------------------------------------------
rssi_dbm        = -68     # Signal strength in dBm (always negative, always int)
channel         = 36      # Wi-Fi channel number
frequency_ghz   = 5.18    # Channel centre frequency — float because of the decimal
throughput_mbps = 945     # Measured throughput in Mbps

print(f"Signal : {rssi_dbm} dBm  | Type: {type(rssi_dbm)}")
print(f"Channel: {channel}       | Type: {type(channel)}")
print(f"Freq   : {frequency_ghz} GHz | Type: {type(frequency_ghz)}")

# Maths with numeric types → the foundation of threshold checks:
rssi_threshold = -75

if rssi_dbm > rssi_threshold:
    print(f"[PASS] Signal {rssi_dbm} dBm is above threshold {rssi_threshold} dBm")
else:
    print(f"[FAIL] Signal {rssi_dbm} dBm is BELOW threshold {rssi_threshold} dBm")
Block 3 — Booleans: For True/False State Flags

Every test ultimately reduces to True or False. Booleans are the backbone of all conditional test logic.

Python 
# --------------------------------------------------
# BLOCK 3: BOOLEANS — True/False state flags
# --------------------------------------------------
is_connected     = True
is_hidden_ssid   = False
supports_wifi6   = True    # 802.11ax capable?
has_valid_ip     = False   # Did DHCP assign an IP?

print(f"Connected  : {is_connected}")
print(f"Wi-Fi 6 AP : {supports_wifi6}")

# Combining booleans with 'and' / 'or' / 'not':
if is_connected and has_valid_ip:
    print("[PASS] Connected and has valid IP")
elif is_connected and not has_valid_ip:
    print("[FAIL] Connected but no IP — likely a DHCP issue")
else:
    print("[FAIL] Not connected at all")
Block 4 — Lists: For Ordered Collections

When you have multiple values of the same kind — a test plan with 10 SSIDs, a set of allowed channels, a history of RSSI readings — use a list. Lists keep things in order and let you loop over them.

Python 
# --------------------------------------------------
# BLOCK 4: LISTS — ordered collections
# --------------------------------------------------
test_ssid_list      = ["CorpNet_2G", "CorpNet_5G", "CorpNet_6G", "Guest_WiFi"]
dfs_free_channels   = [36, 40, 44, 48, 149, 153, 157, 161, 165]

# Access by index — Python lists start at 0, not 1
print(f"First SSID : {test_ssid_list[0]}")    # CorpNet_2G
print(f"Last SSID  : {test_ssid_list[-1]}")   # Guest_WiFi (negative = count from end)
print(f"Total      : {len(test_ssid_list)}")  # 4

# Add a new SSID to the plan dynamically
test_ssid_list.append("IoT_Sensors")
print(f"Updated    : {test_ssid_list}")

# Check membership — this is how you validate a scanned SSID is in your test plan
target = "CorpNet_5G"
if target in test_ssid_list:
    print(f"'{target}' is in the test plan — proceed with test")
Block 5 — Dictionaries: For Structured AP Profiles

A dictionary stores data as key: value pairs — like a form with labelled fields filled in. This is how you represent a full AP profile, a single scan result, or a test configuration. It is the most important data structure you will use throughout this course.

Python 
# --------------------------------------------------
# BLOCK 5: DICTIONARIES — structured key:value records
# --------------------------------------------------

# A complete profile for one AP under test
ap_profile = {
    "ssid"          : "CorpNet_5G",
    "bssid"         : "AA:BB:CC:DD:EE:FF",
    "security"      : "WPA3-SAE",
    "password"      : "Sup3rS3cure!",
    "band"          : "5GHz",
    "channel"       : 36,
    "expected_rssi" : -70,         # Minimum acceptable signal in dBm
    "expected_std"  : "802.11ax"   # Expected Wi-Fi generation (Wi-Fi 6)
}

# Access values by their key name
print(f"Testing    : {ap_profile['ssid']}")
print(f"Min signal : {ap_profile['expected_rssi']} dBm")
print(f"Security   : {ap_profile['security']}")

# A list of dictionaries = a table of scan results (this is what real scan data looks like)
scan_results = [
    {"ssid": "CorpNet_5G",  "rssi": -62, "channel": 36, "security": "WPA3"},
    {"ssid": "CorpNet_2G",  "rssi": -71, "channel": 6,  "security": "WPA2"},
    {"ssid": "Neighbor_AP", "rssi": -88, "channel": 6,  "security": "WPA2"},
]

print("\n--- Scan Results ---")
for ap in scan_results:
    # :<15 left-aligns text in 15 characters; :>4 right-aligns number in 4 characters
    print(f"  {ap['ssid']:<15} | {ap['rssi']:>4} dBm | Ch {ap['channel']:>3} | {ap['security']}")
Block 6 — Putting It All Together: A Mini AP Evaluator

This is the payoff. Using everything from Blocks 1–5, we build a function that compares a live scan result against an expected AP profile and returns a structured pass/fail verdict. This is the exact pattern at the core of every WLAN automated test you will ever write.

Python 
# --------------------------------------------------
# BLOCK 6: THE PAYOFF — Mini AP Evaluation Engine
# --------------------------------------------------

def evaluate_ap(scan_result: dict, expected: dict) -> dict:
    """
    Compare a live scan result against an expected AP profile.
    Returns a results dict with individual check verdicts + an overall verdict.
    """
    results = {}

    # Check 1: Does the SSID match what we expect?
    results["ssid_match"]  = (scan_result["ssid"] == expected["ssid"])

    # Check 2: Is signal strength at or above the minimum threshold?
    results["rssi_ok"]     = (scan_result["rssi"] > expected["expected_rssi"])

    # Check 3: Is the security protocol correct?
    results["security_ok"] = (scan_result["security"] == expected["security"])

    # Overall: every single check must pass for the AP to pass
    # all() returns True only if every value in the list is True
    results["overall"] = all([
        results["ssid_match"],
        results["rssi_ok"],
        results["security_ok"]
    ])

    return results


# --- Simulate what a real live scan would return ---
live_scan = {
    "ssid"    : "CorpNet_5G",
    "rssi"    : -62,
    "security": "WPA3"
}

# Run the evaluation
outcome = evaluate_ap(live_scan, ap_profile)

# Print a clean report
print("\n" + "=" * 45)
print("  AP EVALUATION REPORT")
print("=" * 45)
print(f"  SSID Match    : {'PASS ✓' if outcome['ssid_match'] else 'FAIL ✗'}")
print(f"  Signal (RSSI) : {'PASS ✓' if outcome['rssi_ok']    else 'FAIL ✗'}")
print(f"  Security Type : {'PASS ✓' if outcome['security_ok'] else 'FAIL ✗'}")
print("-" * 45)
print(f"  Overall Result: {'[ PASS ]' if outcome['overall'] else '[ FAIL ]'}")
print("=" * 45)


if __name__ == "__main__":
    pass  # All blocks above run at the module level for learning clarity
