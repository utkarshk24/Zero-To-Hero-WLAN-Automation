The 'Why' — Conceptual Breakdown

Scripts vs. Tests

Your Phase 3 scripts verify connection quality — but they print results to a terminal and exit. A pytest test suite does something fundamentally different: it structures assertions as pass/fail facts, generates machine-readable reports, integrates with CI systems, and allows test selection, parallelisation, and retrying failed tests automatically.

pytest's power is in its convention-over-configuration approach.
Name a file test_*.py and a function test_* inside it, and pytest finds and runs it automatically — no registration, no test class required. Write assert result == expected and pytest gives you a beautiful diff when it fails. That's the whole framework in two sentences.

The assert Statement in pytest

In raw Python, assert x == y raises an obscure AssertionError with no context. pytest rewrites assert statements at import time — when the assertion fails, it shows you the actual values of x and y, any list differences, dict key mismatches, and string diffs. This context is invaluable for diagnosing WLAN test failures.

Block 1 — Test Naming Convention and Basic Assertions

pytest discovers any function that starts with test_ in any file that starts with test_. No inheritance, no boilerplate — just functions and asserts.

Python test_day27.py

# Run with: pytest test_day27.py -v

# Import the function we want to test (from Day 4's wlan_utils.py)
# Using inline implementations here for self-contained demo

def classify_signal(rssi):
    """Classify RSSI dBm value into quality label."""
    if rssi >= -50: return "Excellent"
    if rssi >= -60: return "Good"
    if rssi >= -70: return "Fair"
    return "Poor"

def rssi_to_percent(rssi):
    """Convert RSSI to 0-100% quality score."""
    rssi = max(-100, min(-50, rssi))
    return int((rssi + 100) * 2)

# ── Block 1: Basic assertions ──────────────────────────────────

def test_classify_excellent():
    """RSSI of -42 should be Excellent."""
    assert classify_signal(-42) == "Excellent"

def test_classify_good():
    assert classify_signal(-58) == "Good"

def test_classify_fair():
    assert classify_signal(-67) == "Fair"

def test_classify_poor():
    assert classify_signal(-81) == "Poor"

def test_classify_boundary_excellent():
    """Test the boundary value: -50 should be Excellent."""
    assert classify_signal(-50) == "Excellent"

def test_classify_boundary_good():
    """-51 should be Good (just below Excellent boundary)."""
    assert classify_signal(-51) == "Good"

def test_rssi_to_percent_min():
    """RSSI -100 dBm should map to 0%."""
    assert rssi_to_percent(-100) == 0

def test_rssi_to_percent_max():
    """RSSI -50 dBm (clamped max) should map to 100%."""
    assert rssi_to_percent(-50) == 100

def test_rssi_to_percent_middle():
    """RSSI -75 dBm should map to 50%."""
    assert rssi_to_percent(-75) == 50
Block 2 — pytest.raises() and Expected Failures

pytest.raises() is a context manager that asserts a specific exception IS raised. This is essential for testing error handling — you want to verify that invalid inputs raise the right errors.

Python 
import pytest

def parse_channel(channel_str):
    """Parse a channel string to int; raise ValueError for invalid input."""
    ch = int(channel_str)
    if ch < 1 or ch > 165:
        raise ValueError(f"Channel {ch} is out of valid range 1-165")
    return ch

# ── Block 2: Testing exceptions ────────────────────────────────

def test_parse_channel_valid():
    assert parse_channel("36") == 36

def test_parse_channel_invalid_range():
    """Channel 200 should raise ValueError."""
    with pytest.raises(ValueError, match="out of valid range"):
        parse_channel("200")

def test_parse_channel_invalid_type():
    """Non-numeric string should raise ValueError."""
    with pytest.raises(ValueError):
        parse_channel("notachannel")

# ── Block 3: pytest.mark for skipping and expected failures ────

@pytest.mark.skip(reason="Requires physical Wi-Fi adapter")
def test_live_rssi():
    """This test needs real hardware — skip in CI without adapter."""
    from Day24_rssi_monitor import get_rssi
    rssi = get_rssi("wlan0")
    assert rssi is not None
    assert -100 <= rssi <= 0

@pytest.mark.xfail(reason="Known nmcli bug on Ubuntu 20.04 — fix pending")
def test_known_broken_feature():
    """Mark tests as expected-to-fail without removing them."""
    # This assertion is known to fail — logged as xfail, not FAIL
    assert parse_channel("0") == 0   # 0 should fail our range check
Block 4 — Running pytest and Reading Output
Bash 
# Run all tests in verbose mode
pytest test_day27.py -v

# Run only tests matching a keyword
pytest test_day27.py -v -k "boundary"

# Run and stop on first failure
pytest test_day27.py -v -x

# Show extra information on failure (full local variables)
pytest test_day27.py -v --tb=long

# Count passing, failing, skipped
pytest test_day27.py -v --tb=short -q
