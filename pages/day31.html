The 'Why' — Conceptual Breakdown

Why HTML Reports Matter

A CI pipeline that only prints "42 passed, 3 failed" to a log file is useless for a WLAN deployment review meeting. Your network manager needs a report they can open in a browser, with a green/red summary table, timestamps, AP names, and attached evidence (RSSI charts, PCAP links). pytest-html generates this from your existing pytest suite with zero code changes to your tests.

pytest-html reports are self-contained single HTML files.
All CSS, JavaScript, and embedded test data are in one file. Share it via email, attach to a Jira ticket, or publish to GitHub Pages (Day 37). No web server required to view it.

Block 2 — pytest_configure for Custom Metadata

The pytest_configure hook in conftest.py lets you add custom metadata to every report — test environment, device under test, firmware version, site name, and engineer name.

Python conftest.py 
# Add to conftest.py

import datetime

def pytest_configure(config):
    """
    pytest_configure hook — called once before any tests run.
    Used to add custom metadata to the HTML report header.
    """
    config._metadata = getattr(config, "_metadata", {})
    config._metadata["Test Site"]         = "HQ-Floor-3"
    config._metadata["AP Inventory"]      = "ap_inventory.json"
    config._metadata["Test Environment"]  = "Staging"
    config._metadata["Test Engineer"]     = "WLAN Automation Bot"
    config._metadata["Run Timestamp"]     = datetime.datetime.now().isoformat()
    config._metadata["Min RSSI Threshold"]= "-75 dBm"
Block 3 — Attaching Evidence with extra.append()

The extras parameter in the test report hook allows attaching additional context to individual test results. Attach RSSI values, scan output, or even base64-encoded screenshots.

Python conftest.py 
from pytest_html import extras

def pytest_runtest_makereport(item, call):
    """
    Hook called after each test phase (setup/call/teardown).
    Used to attach extra context to the HTML report for failing tests.
    """
    if call.when == "call" and call.excinfo:
        # Only attach extras on test failure (excinfo = exception info)
        pass   # Extra logic in tests using 'extra' fixture below

@pytest.fixture
def add_report_extra(request, extra):
    """
    Fixture that lets tests attach extra data to their HTML report entry.
    Usage: add_report_extra.append(extras.html("<b>custom content</b>"))
    """
    yield extra   # 'extra' is provided by pytest-html automatically
Block 4 — pytest.ini addopts for Auto-Report

Adding addopts to pytest.ini means you never need to type --html again. Every pytest run automatically generates the report.

Bash pytest.ini 
# pytest.ini — project-level pytest configuration
[pytest]
# addopts: these flags are ALWAYS passed to pytest automatically
addopts =
    --html=reports/latest_report.html
    --self-contained-html
    -v

# Register custom marks to avoid PytestUnknownMarkWarning
markers =
    slow: mark test as requiring real hardware or network
    smoke: quick smoke test for CI gatekeeping
    integration: requires live AP connection

# Minimum pytest version
minversion = 7.0

# Test discovery paths
testpaths = tests

Hands-on Exercise — Your Turn

Customise the HTML report with WLAN-specific evidence:

  • Task 1: In a failing RSSI test, use extras.html() to append a formatted HTML table showing each AP's SSID, RSSI, and pass/fail status to the test's report entry. This table should appear inline in the HTML report under the failed test.
  • Task 2: Add a pytest_sessionfinish hook in conftest.py that prints the report file path and total duration at the end of every test session. This makes the report URL easy to find in CI logs.
  • Bonus: Install pytest-metadata and add the current Git commit SHA and branch name to the report metadata using subprocess.run(["git", "rev-parse", "--short", "HEAD"]) — so every report is traceable to the exact code version that generated it.
Hint: The extra fixture from pytest-html is injected automatically when you include it as a parameter. Use extra.append(extras.html("<table>...</table>")) to attach an HTML fragment. The extras.url("http://...", "Link text") function attaches a clickable link — great for linking to Kibana dashboards.
