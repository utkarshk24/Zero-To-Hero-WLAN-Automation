Introduction to GitHub Actions
CI/CD

Your test suite runs manually today. Tomorrow it runs automatically on every commit. Today you'll write GitHub Actions workflow files that install dependencies, run pytest, and publish reports — so every push to your repo is automatically tested.

The 'Why' — Conceptual Breakdown

Manual Testing vs. Automated CI

Manual testing: you clone the repo, install dependencies, run pytest locally, then git push. A teammate clones the same repo, runs the same tests, and gets a different result. Did the code break, or did they miss a dependency?

Automated CI: the repository itself runs the tests on every push. If a test fails, the build is red. You can't merge until tests pass. Everyone sees the same results in the same environment.

GitHub Actions is free for public repositories.
Every push triggers a workflow. GitHub provides runners (Ubuntu, macOS, Windows), so your tests execute in a clean environment every time. You don't need to maintain your own CI server — GitHub does it for you.
💻

Code Walkthrough — Building Your First Workflow

GitHub Actions workflows live in .github/workflows/ and are written in YAML. A workflow defines jobs, steps, triggers, and artifacts. When you push code, GitHub reads the workflow and executes it.

Block 1 — Your First Workflow: run pytest on push
yaml .github/workflows/test.yml 
name: WLAN Automation Tests

on:
  push:
    branches: [ main, develop ]
  pull_request:
    branches: [ main ]

jobs:
  test:
    runs-on: ubuntu-latest

    steps:
      - name: Checkout repository
        uses: actions/checkout@v4

      - name: Set up Python
        uses: actions/setup-python@v5
        with:
          python-version: "3.12"

      - name: Install dependencies
        run: |
          python -m pip install --upgrade pip
          pip install -r requirements.txt

      - name: Run tests (unit tests only — no hardware needed)
        run: pytest -m "not live" -v --html=reports/report.html --self-contained-html

      - name: Upload HTML report
        uses: actions/upload-artifact@v4
        if: always()   # upload even if tests fail
        with:
          name: test-report-${{ github.run_number }}
          path: reports/report.html
Block 2 — Matrix Strategy (test multiple Python versions)

Test your code on Python 3.10, 3.11, and 3.12 in parallel. If any version fails, the entire job fails. This catches version-specific bugs early.

yaml .github/workflows/test.yml 
jobs:
  test:
    runs-on: ubuntu-latest
    strategy:
      matrix:
        python-version: ["3.10", "3.11", "3.12"]

    steps:
      - uses: actions/checkout@v4

      - name: Set up Python ${{ matrix.python-version }}
        uses: actions/setup-python@v5
        with:
          python-version: ${{ matrix.python-version }}

      - name: Install and test
        run: |
          pip install -r requirements.txt
          pytest -m "not live" -v
Block 3 — Publishing Allure Reports to GitHub Pages

After every test run, generate an Allure report and deploy it to GitHub Pages. Stakeholders can view the latest results without leaving GitHub.

yaml .github/workflows/test.yml 
      - name: Run tests with Allure
        run: pytest -m "not live" --alluredir=allure-results

      - name: Generate Allure report
        uses: simple-elf/allure-report-action@master
        if: always()
        with:
          allure_results: allure-results
          allure_history: allure-history

      - name: Deploy Allure report to GitHub Pages
        uses: peaceiris/actions-gh-pages@v3
        if: always()
        with:
          github_token: ${{ secrets.GITHUB_TOKEN }}
          publish_branch: gh-pages
          publish_dir: allure-history
Block 4 — Useful Workflow Patterns

Skip CI for certain file changes, pass secrets securely, and cache dependencies to speed up your workflows.

yaml .github/workflows/test.yml 
# Run only on specific file changes (skip CI for docs changes)
on:
  push:
    paths:
      - 'src/**'
      - 'tests/**'
      - 'requirements.txt'

# Pass secrets as environment variables (never hardcode credentials)
    steps:
      - name: Run with credentials
        env:
          WIFI_PASSWORD: ${{ secrets.CORP_WIFI_PASSWORD }}
          AP_INVENTORY:  ${{ secrets.AP_INVENTORY_PATH }}
        run: pytest

# Cache pip dependencies (faster CI runs)
      - name: Cache pip
        uses: actions/cache@v4
        with:
          path: ~/.cache/pip
          key: ${{ runner.os }}-pip-${{ hashFiles('requirements.txt') }}

GitHub Actions Concepts at a Glance

ConceptMeaningExample
WorkflowAutomated process defined in YAML.github/workflows/test.yml
TriggerEvent that starts the workflowpush, pull_request, schedule
JobSet of steps that run on a runnertest, build, deploy
StepIndividual task (action or shell command)checkout, setup-python, pytest
RunnerVirtual machine where jobs executeubuntu-latest, windows-latest
ArtifactOutput files saved from a jobHTML reports, logs, coverage
SecretEncrypted environment variableAPI keys, passwords (never in code)

Create a GitHub Actions workflow that automates your WLAN test suite:
