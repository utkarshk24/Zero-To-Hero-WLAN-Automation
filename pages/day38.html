CI Pipelines

On-push CI catches code bugs. Nightly CI catches environmental regressions — APs that drifted, DHCP servers that changed, new interference sources. Today you'll set up a scheduled nightly test pipeline with trend tracking and email/Slack alerts.

The 'Why' — Conceptual Breakdown

On-Push CI vs. Nightly CI

On-push CI runs when developers commit. It catches code bugs: "Did I break something when I refactored the DHCP validation function?" Nightly CI runs on a schedule and tests the environment: "Did an AP firmware update change beacon behavior? Did the DHCP server get reconfigured? Is there new interference?"

Environmental regressions happen silently. Your code works fine, but the lab APs degrade or network configs change. Nightly tests catch these shifts before they impact production.

Trend-based alerting is smarter than hard thresholds.
An RSSI of -65 dBm might be normal for AP-01 but low for AP-02. Instead of hardcoding "alert if RSSI < -70," compare today's RSSI to the rolling average of the past 7 days. Alert only if it dropped by 5+ dBm — a real regression.
💻

Code Walkthrough — Nightly Workflows & Alerts

Nightly workflows run on a schedule (GitHub Actions cron syntax) and can use self-hosted runners (your lab machines with Wi-Fi hardware). They measure baselines, detect regressions, and alert via email or Slack.

Block 1 — Scheduled Nightly Workflow
yaml .github/workflows/nightly.yml 
name: Nightly WLAN Regression

on:
  schedule:
    - cron: '0 23 * * *'   # 11 PM UTC every night
  workflow_dispatch:         # manual trigger from GitHub UI

jobs:
  nightly-regression:
    runs-on: self-hosted   # must be your lab machine with Wi-Fi hardware
    timeout-minutes: 60

    steps:
      - uses: actions/checkout@v4

      - name: Install dependencies
        run: pip install -r requirements.txt

      - name: Run full regression suite
        env:
          TEST_ENV: nightly
          AP_INVENTORY: ${{ secrets.AP_INVENTORY }}
        run: |
          pytest tests/ \
            --html=reports/nightly_report.html \
            --junit-xml=reports/nightly_results.xml \
            --alluredir=reports/allure-results \
            -v 2>&1 | tee reports/nightly.log

      - name: Upload all reports
        uses: actions/upload-artifact@v4
        if: always()
        with:
          name: nightly-report-${{ github.run_number }}
          path: reports/
          retention-days: 30
Block 2 — Tracking RSSI Trends Across Nightly Runs

Store RSSI readings in a JSON file. Compare today's readings to the 7-day rolling average. If any AP's signal dropped >5 dBm, flag it as a regression.

python Day38_nightly_trends.py 
import json, datetime, os

TREND_FILE = "reports/rssi_trend.json"

def save_nightly_rssi(ap_results):
    """Append today's RSSI readings to the trend file."""
    trend = []
    if os.path.exists(TREND_FILE):
        with open(TREND_FILE) as f:
            trend = json.load(f)

    trend.append({
        "date":   datetime.date.today().isoformat(),
        "aps":    ap_results,
    })
    with open(TREND_FILE, "w") as f:
        json.dump(trend, f, indent=2)


def detect_rssi_regression(ssid, window=7, drop_threshold=5):
    """
    Alert if an AP's average RSSI dropped by more than drop_threshold dBm
    compared to the rolling average of the last 'window' days.
    """
    if not os.path.exists(TREND_FILE):
        return None

    with open(TREND_FILE) as f:
        trend = json.load(f)

    history = []
    for day in trend[-window:]:
        for ap in day["aps"]:
            if ap["ssid"] == ssid:
                history.append(ap["rssi"])

    if len(history) < 2:
        return None

    baseline = sum(history[:-1]) / len(history[:-1])
    latest   = history[-1]
    delta    = baseline - latest   # positive = signal got weaker

    if delta >= drop_threshold:
        print(f"  ⚠️  REGRESSION: {ssid} RSSI dropped {delta:.1f} dB "
              f"(baseline: {baseline:.1f}, today: {latest})")
        return delta
    return None
Block 3 — Sending Nightly Alert Emails

After the nightly tests complete, check for failures or regressions. If found, send an alert email with details. Use environment variables for SMTP credentials.

python Day38_nightly_trends.py 
import smtplib, os
from email.mime.text import MIMEText
from email.mime.multipart import MIMEMultipart

def send_alert(subject, body, to_email):
    """Send a test alert email using SMTP (credentials from env vars)."""
    smtp_server = os.environ.get("SMTP_SERVER", "smtp.gmail.com")
    smtp_port   = int(os.environ.get("SMTP_PORT", "587"))
    from_email  = os.environ["SMTP_FROM"]
    password    = os.environ["SMTP_PASSWORD"]

    msg = MIMEMultipart()
    msg["From"]    = from_email
    msg["To"]      = to_email
    msg["Subject"] = subject
    msg.attach(MIMEText(body, "plain"))

    with smtplib.SMTP(smtp_server, smtp_port) as server:
        server.starttls()
        server.login(from_email, password)
        server.send_message(msg)
    print(f"Alert sent to {to_email}")


def nightly_alert_if_failed(results, to_email):
    """Alert if any test failed."""
    failed = [r["ssid"] for r in results if r["result"] != "PASS"]
    if failed:
        subject = f"[WLAN CI] {len(failed)} test(s) FAILED — {datetime.date.today()}"
        body    = f"Failed SSID(s):\n" + "\n".join(f"  - {s}" for s in failed)
        send_alert(subject, body, to_email)
Block 4 — Post-Test Hook (conftest.py)

Use pytest's pytest_sessionfinish hook to run custom logic after all tests complete. Read JUnit XML, count failures, and trigger alerts.

python conftest.py 
import pytest, os, xml.etree.ElementTree as ET
from datetime import date
from Day38_nightly_trends import send_alert

def pytest_sessionfinish(session, exitstatus):
    """Hook that runs after all tests complete."""
    # Only alert for nightly runs
    if os.environ.get("TEST_ENV") != "nightly":
        return

    xml_file = "reports/nightly_results.xml"
    if not os.path.exists(xml_file):
        return

    # Parse JUnit XML to count failures
    tree = ET.parse(xml_file)
    root = tree.getroot()
    passed  = len(root.findall(".//testcase[not(failure|error)]"))
    failed  = len(root.findall(".//testcase[failure or error]"))
    total   = passed + failed

    if failed > 0:
        subject = f"[Nightly CI] {failed}/{total} tests FAILED — {date.today()}"
        body    = f"Passed: {passed}\nFailed: {failed}\n\n" \
                  f"View full report: {os.environ.get('CI_BUILD_URL', 'N/A')}"
        send_alert(subject, body, os.environ["ALERT_EMAIL"])
        print(f"[Alert] {failed} test(s) failed. Email alert sent.")
