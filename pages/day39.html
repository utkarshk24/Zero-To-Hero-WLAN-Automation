Secrets & Environment
Configuration

Wi-Fi passwords, AP credentials, and SMTP keys don't belong in code. Today you'll master the right way to manage secrets in Python automation — python-dotenv locally, GitHub Secrets in CI, and runtime validation so tests fail fast with a clear message if config is missing.

The 'Why' — Conceptual Breakdown

Hardcoded Secrets = Disaster Waiting to Happen

You hardcode WIFI_PASSWORD = "CorpWifi2024" in your test file. You commit it to GitHub. Someone forks your repo. The password is public forever. HR gets a call from the security team.

Secrets must live outside your code. Locally, they go in .env files that git ignores. In CI, they go in GitHub Secrets, which GitHub redacts from logs. Your code reads from environment variables — never from files or hardcoded strings.

Fail fast on missing config.
Don't let tests run if required secrets are missing. Validate at startup and raise a clear error. "Missing WIFI_PASSWORD" is better than a cryptic "Connection refused" from a test 20 minutes into the run.
💻

Code Walkthrough — Secrets Management

Secrets flow through three layers: local .env files, GitHub Secrets vault, and runtime environment variables. At each layer, validate and fail fast if something is missing.

Block 2 — .gitignore: Never Commit Secrets

Add secret file patterns to .gitignore BEFORE your first commit. Git won't track them, so you can't accidentally commit them.

bash .gitignore 
# .gitignore — add these BEFORE your first commit
.env
.env.*
*.env
secrets/
credentials.json
ap_passwords.yaml

# Check if you've accidentally staged a secret file:
git status --short | grep "\.env"

# If .env was already committed — remove it:
git rm --cached .env
echo ".env" >> .gitignore
git commit -m "Remove .env from tracking"
Block 3 — GitHub Secrets for CI

In GitHub's web UI, go to Settings → Secrets and variables → Actions. Add secrets there. Reference them in your workflow with ${{ secrets.NAME }} and pass them as environment variables.

yaml .github/workflows/test.yml 
# In GitHub repo: Settings → Secrets and variables → Actions
# Add secrets: WIFI_SSID, WIFI_PASSWORD, MIN_RSSI

# Use them in workflow:
# .github/workflows/test.yml
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Run WLAN tests
        env:
          WIFI_SSID:     ${{ secrets.WIFI_SSID }}
          WIFI_PASSWORD: ${{ secrets.WIFI_PASSWORD }}
          MIN_RSSI:      ${{ secrets.MIN_RSSI }}
        run: pytest tests/ -m "not live" -v
Block 4 — Config Validation at Startup

Create a centralized config loader that validates all required variables exist. If any are missing, pytest fails immediately with a clear error message.

python config.py 
# config.py — centralised config loader with validation

import os
from dotenv import load_dotenv

load_dotenv()

REQUIRED_VARS = ["WIFI_SSID", "WIFI_PASSWORD"]
OPTIONAL_VARS = {
    "MIN_RSSI":     "-70",
    "TEST_ENV":     "local",
    "AP_INTERFACE": "wlan0",
    "IPERF_SERVER": "192.168.1.100",
}

def load_config():
    """Load and validate all required environment variables."""
    missing = [v for v in REQUIRED_VARS if not os.environ.get(v)]
    if missing:
        raise EnvironmentError(
            f"Missing required environment variables: {missing}\n"
            f"Copy .env.example to .env and fill in the values."
        )
    config = {v: os.environ[v] for v in REQUIRED_VARS}
    config.update({k: os.environ.get(k, default) for k, default in OPTIONAL_VARS.items()})
    config["MIN_RSSI"] = int(config["MIN_RSSI"])
    return config

Block 5 — .env.example: Document Config

Commit .env.example to git. It documents which variables are required and what formats they expect — without exposing actual values. New developers copy it to .env and fill in their values.

bash .env.example 
# .env.example — commit this! Documents config without exposing values.

WIFI_SSID=your_ssid_here
WIFI_PASSWORD=your_password_here
AP_ADMIN_USER=admin
AP_ADMIN_PASS=change_me
MIN_RSSI=-70
TEST_ENV=local
AP_INTERFACE=wlan0
IPERF_SERVER=192.168.1.100
SMTP_FROM=alerts@yourcompany.com
SMTP_PASSWORD=app_password_here
SMTP_SERVER=smtp.gmail.com
SMTP_PORT=587

Hands-on Exercise — Your Turn

Refactor your test suite to use secure secrets management:

  • Task 1: Create a config.py with a load_config() function that loads from .env using python-dotenv. Define REQUIRED_VARS (e.g., WIFI_SSID, WIFI_PASSWORD) and OPTIONAL_VARS (e.g., MIN_RSSI with a default of "-70"). Raise EnvironmentError if any required variable is missing.

Hint: Use @pytest.fixture(scope="session") in conftest.py to load config once at the start of the entire test run. This ensures all tests see the same validated config. If load_config() raises an exception, pytest stops before running any tests.
