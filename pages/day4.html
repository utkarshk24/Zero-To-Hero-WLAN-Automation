The 'Why' — Conceptual Breakdown

The Copy-Paste Trap

In Days 1–3 you wrote scripts that ran top to bottom — great for one-offs. But real WLAN automation means running the same signal check on 50 APs, across 3 test suites, on 5 different machines, inside CI pipelines.

Without functions, you copy-paste the same 8-line block everywhere. Then a threshold changes from -70 to -72 dBm. You have to find and update 14 copies. You miss two. Two tests now report wrong results. Your manager asks why.

Functions are the antidote to copy-paste.
Write the logic once, name it clearly, call it anywhere. When the threshold changes, you change it in one place — and every single script that calls the function gets the update automatically.

What Functions Give You

  • DRY code — Don't Repeat Yourself. Write once, call anywhere.
  • Testability — Test each function in isolation before wiring it into a larger script.
  • Readability — check_signal(rssi) tells you exactly what it does. A 10-line if/elif block does not.
  • Reuse across projects — Build a personal wlan_utils.py toolkit you import into every future script.

Block 1 — Anatomy of a Python Function

Every function has the same skeleton. The def keyword declares it, the name describes what it does, parameters are the inputs, and return sends a value back to whoever called it.

Python Day04_functions.py 
def classify_signal(rssi):
    """
    Classify Wi-Fi signal strength from an RSSI dBm value.
    Returns: 'Excellent', 'Good', 'Fair', or 'Poor'
    """
    if rssi >= -50:
        return "Excellent"
    elif rssi >= -60:
        return "Good"
    elif rssi >= -70:
        return "Fair"
    else:
        return "Poor"


# --- Call the function ---
test_values = [-42, -58, -67, -81]
for rssi in test_values:
    quality = classify_signal(rssi)
    print(f"RSSI {rssi:4d} dBm  →  {quality}")
Block 2 — Default Parameters & Keyword Arguments

Default values make functions flexible. Callers only pass what they need to override — everything else uses a sensible default. This is how you write one function that handles both quick checks and detailed validation.

Python 
def evaluate_ap(ssid, rssi, channel=6, security="WPA2", min_rssi=-70):
    """
    Evaluate an AP against pass/fail criteria.
    min_rssi has a default so quick calls don't need to specify it.
    """
    passed = (rssi >= min_rssi) and (security in ("WPA2", "WPA3"))
    status = "PASS ✓" if passed else "FAIL ✗"
    print(f"  [{status}] {ssid:20s} | RSSI: {rssi} dBm | Ch: {channel} | Sec: {security}")
    return passed


# Minimal call — uses all defaults
evaluate_ap("CorpWifi",  rssi=-55)

# Full override — every argument specified
evaluate_ap("GuestWifi", rssi=-75, channel=11, security="Open", min_rssi=-70)

# Keyword args — order doesn't matter when you name them
evaluate_ap(ssid="LabAP-5G", rssi=-48, security="WPA3", channel=36)
Block 3 — Returning Multiple Values

Python functions can return a tuple — multiple values at once. Perfect for returning a result AND a human-readable reason together, so the caller can log or display both without calling the function twice.

Python 
def check_channel_overlap(ch1, ch2):
    """
    Check if two 2.4 GHz channels cause interference.
    Non-overlapping channels in 2.4 GHz: 1, 6, 11
    Returns: (overlaps: bool, reason: str)
    """
    non_overlapping = {1, 6, 11}

    if ch1 == ch2:
        return True, f"Both APs on channel {ch1} — direct co-channel interference"

    if ch1 not in non_overlapping or ch2 not in non_overlapping:
        return True, f"Ch {ch1} or Ch {ch2} is not a non-overlapping channel"

    return False, f"Channels {ch1} and {ch2} are non-overlapping — no interference"


# Unpack both return values at once
overlaps, reason = check_channel_overlap(6, 6)
print(f"  Overlap: {overlaps}  →  {reason}")

overlaps, reason = check_channel_overlap(1, 11)
print(f"  Overlap: {overlaps}  →  {reason}")
Block 4 — Building Your Personal wlan_utils Module

Save your functions in a separate file called wlan_utils.py. Every future script imports from it — one source of truth for all your WLAN logic.

Python wlan_utils.py 
# wlan_utils.py  ← Your personal WLAN toolkit — grows throughout this course

def rssi_to_percent(rssi):
    """Convert RSSI dBm to a 0–100 quality percentage."""
    rssi = max(-100, min(-50, rssi))    # clamp to -100…-50 range
    return int((rssi + 100) * 2)        # -100 → 0%, -50 → 100%


def is_5ghz_channel(channel):
    """Return True if the channel number belongs to the 5 GHz band."""
    return channel >= 36


def format_bssid(raw):
    """Normalise any BSSID format to uppercase AA:BB:CC:DD:EE:FF."""
    clean = raw.replace("-", ":").upper()
    if len(clean) == 12:                # no separators: AABBCCDDEEFF
        clean = ":".join(clean[i:i+2] for i in range(0, 12, 2))
    return clean


def ap_summary(ssid, bssid, rssi, channel):
    """Return a one-line human-readable AP summary string."""
    band  = "5 GHz" if is_5ghz_channel(channel) else "2.4 GHz"
    qual  = rssi_to_percent(rssi)
    bssid = format_bssid(bssid)
    return f"{ssid} [{bssid}] Ch{channel} ({band})  {rssi} dBm  ({qual}%)"

from wlan_utils import classify_signal, ap_summary

# Simulate a scan result
scan_results = [
    {"ssid": "CorpAP-1",  "bssid": "00:11:22:33:44:01", "rssi": -52, "channel": 1},
    {"ssid": "CorpAP-2",  "bssid": "00:11:22:33:44:02", "rssi": -68, "channel": 6},
    {"ssid": "CorpAP-5G", "bssid": "00:11:22:33:44:03", "rssi": -45, "channel": 36},
]

print("=== AP Scan Report ===")
for ap in scan_results:
    summary = ap_summary(ap["ssid"], ap["bssid"], ap["rssi"], ap["channel"])
    quality = classify_signal(ap["rssi"])
    print(f"  {summary}  —  {quality}")
