The 'Why' — Conceptual Breakdown

Why Files Matter in Automation

Manual testers write results in spreadsheets. Automated testers write results to files. The difference: a script can produce a perfectly formatted, timestamped CSV report in milliseconds, attach it to a CI artefact, email it to a manager, and archive it — all without any human intervention. This is the power of File I/O.

Three file formats power 90% of WLAN automation logging.
Key=Value configs for test parameters. Plain text logs for timestamped event history. CSV files for tabular test results that open in Excel or feed into dashboards.

Python's Context Manager Pattern

Python uses the with open(...) as f: pattern to open files safely. When the with block exits — even if an exception is raised inside it — Python automatically closes the file and flushes any buffered writes to disk. Never use f = open(...) without with in production scripts. A crash mid-write without proper closing corrupts the file.

pathlib: Cross-Platform Paths

Python 3.4+ includes pathlib, an object-oriented way to handle file paths. Instead of fragile string concatenation like "logs/" + filename + ".csv", you write Path("logs") / filename. The / operator on Path objects works correctly on every OS — no more backslash vs. forward-slash bugs between Windows and Linux in your test scripts.

Block 1 — Reading a key=value Config File

Simple config files with KEY=VALUE lines are the most portable format for test parameters — no special library needed, and any text editor can modify them. This is how SSH configs, .env files, and many network device configs are structured.

Python Day06_file_io.py 
# =============================================================
# Day 6: File I/O — Config files, log files, CSV results
# =============================================================

from pathlib import Path
import csv
import datetime

# ── Block 1: Read a key=value config file ────────────────────

SAMPLE_CONFIG = """# WLAN Test Configuration
SSID=CorpWifi-5G
MIN_RSSI=-70
SECURITY=WPA2
TEST_DURATION=60
LOG_LEVEL=INFO
"""

def read_config(filepath):
    """
    Parse a key=value config file into a Python dict.
    Lines starting with '#' are comments — ignored.
    Blank lines are also skipped safely.
    """
    config = {}
    with open(filepath, "r") as f:
        for line in f:
            line = line.strip()
            # Skip comments and blank lines
            if not line or line.startswith("#"):
                continue
            # .partition("=") splits on first '=' only — safe if value contains '='
            key, _, value = line.partition("=")
            config[key.strip()] = value.strip()
    return config

# Write sample config file then read it back
config_path = Path("test_config.ini")
config_path.write_text(SAMPLE_CONFIG)

config = read_config(config_path)
print("[Config Loaded]")
for key, value in config.items():
    print(f"  {key:20s} = {value}")
Block 2 — Writing Timestamped Log Files

Every test event should be logged with a timestamp. Python's datetime module gives microsecond precision. The "a" (append) mode adds to an existing file instead of overwriting — essential for accumulating logs across multiple test runs.

Python 
# ── Block 2: Timestamped log writer ──────────────────────────

def log_event(filepath, level, message):
    """
    Append a timestamped log entry to a file.
    Format: [YYYY-MM-DD HH:MM:SS] LEVEL    message
    Mode 'a' = append — never overwrites existing entries.
    """
    timestamp = datetime.datetime.now().strftime("%Y-%m-%d %H:%M:%S")
    line = f"[{timestamp}] {level:<8} {message}\n"

    with open(filepath, "a") as f:   # 'a' appends to existing content
        f.write(line)

    print(line, end="")  # Also echo to console so you can see progress live

# Simulate a test run generating log events
log_path = Path("wlan_test.log")
log_event(log_path, "INFO",    "Test run started")
log_event(log_path, "INFO",    "Connecting to SSID: CorpWifi-5G")
log_event(log_path, "INFO",    "Association successful — IP: 192.168.1.42")
log_event(log_path, "WARNING", "RSSI -72 dBm is below threshold -70 dBm")
log_event(log_path, "INFO",    "Test run completed")
Block 3 — Writing CSV Results with csv.DictWriter

csv.DictWriter writes each row from a Python dictionary, matching dict keys to column headers automatically. This is much safer than manually joining strings with commas — it handles quoting, embedded commas in values, and Unicode characters correctly without any extra code.

Python 
# ── Block 3: Write CSV test results ──────────────────────────

FIELDNAMES = ["timestamp", "ssid", "bssid", "rssi_dbm",
              "channel", "security", "ip_address", "result"]

def write_results_csv(filepath, results):
    """
    Write a list of result dicts to a CSV file.
    newline='' is required on Windows to prevent double line-breaks.
    """
    with open(filepath, "w", newline="") as f:
        writer = csv.DictWriter(f, fieldnames=FIELDNAMES)
        writer.writeheader()      # Writes the column name row first
        writer.writerows(results) # Writes all rows at once

# Simulated scan + connection test results
results = [
    {"timestamp": "2024-01-15 09:00:01", "ssid": "CorpWifi-5G",
     "bssid": "AA:BB:CC:01:02:03", "rssi_dbm": -52, "channel": 36,
     "security": "WPA2", "ip_address": "192.168.1.42", "result": "PASS"},
    {"timestamp": "2024-01-15 09:00:14", "ssid": "CorpWifi-2G",
     "bssid": "AA:BB:CC:01:02:04", "rssi_dbm": -74, "channel": 6,
     "security": "WPA2", "ip_address": "N/A", "result": "FAIL"},
]

csv_path = Path("test_results.csv")
write_results_csv(csv_path, results)
print(f"\n[CSV] Written {len(results)} results to {csv_path}")
Block 4 — Reading and Analysing a CSV Log

csv.DictReader reads each row as a dict, keyed by the header row. This makes it easy to filter, aggregate, and report on accumulated test history — the foundation of a test trend dashboard.

Python 
# ── Block 4: Read and analyse CSV results ────────────────────

def analyse_results_csv(filepath):
    """
    Read a CSV results file and print a pass/fail summary.
    DictReader automatically uses the first (header) row as dict keys.
    """
    passed = []
    failed = []

    with open(filepath, "r") as f:
        reader = csv.DictReader(f)
        for row in reader:
            if row["result"] == "PASS":
                passed.append(row["ssid"])
            else:
                failed.append(row["ssid"])

    total = len(passed) + len(failed)
    pct   = (len(passed) / total * 100) if total > 0 else 0.0
    print(f"\n[Results Summary]")
    print(f"  Total : {total}")
    print(f"  PASS  : {len(passed)}  → {passed}")
    print(f"  FAIL  : {len(failed)}  → {failed}")
    print(f"  Score : {pct:.1f}%")
    return len(failed) == 0   # True = all tests passed

analyse_results_csv(csv_path)
