The 'Why' — Conceptual Breakdown

When key=value Isn't Enough

Yesterday's config file works for a single AP. But a production WLAN test suite might cover 50 APs, each with different SSIDs, security types, expected channels, and minimum RSSI thresholds per location. A flat KEY=VALUE file can't represent that hierarchy cleanly. You'd end up with names like AP1_SSID=CorpWifi, AP1_CHANNEL=36, AP2_SSID=... — a maintenance nightmare.

JSON and YAML are the industry standard for structured configuration.
JSON is the format of REST APIs and data exchange. YAML is the format of CI pipelines, Kubernetes configs, and Ansible playbooks. Both parse into Python dicts and lists — exactly the data structures you already know.

JSON vs. YAML — When to Use Each

JSON (.json) is strict, machine-generated, and universally supported. Use it for AP inventories, test result data, and anything that travels over a REST API. YAML (.yaml) is human-friendly, supports comments, and is less verbose. Use it for test configuration files that engineers edit by hand. Your automation framework will often use both: JSON for data, YAML for config.

Code Walkthrough — JSON Inventory & YAML Config Validation

Create Day07_json_yaml.py. You'll parse a JSON AP inventory, load a YAML test config, then validate simulated scan results against both sources.

Block 1 — Parsing JSON with json.loads / json.dumps

Python's built-in json module converts between JSON strings and Python objects. json.loads() parses a string into a dict. json.dumps() converts a dict back to a formatted JSON string. No installation needed.

Python Day07_json_yaml.py 
# =============================================================
# Day 7: JSON & YAML — Config file parsing and validation
# =============================================================

import json
import yaml    # pip install PyYAML
from pathlib import Path

# ── Block 1: JSON AP Inventory ───────────────────────────────

AP_INVENTORY_JSON = """
{
  "site": "HQ-Floor-3",
  "access_points": [
    {"ssid": "CorpWifi-5G",  "bssid": "AA:BB:CC:01:02:03",
     "channel": 36, "security": "WPA2", "min_rssi": -65},
    {"ssid": "CorpWifi-2G",  "bssid": "AA:BB:CC:01:02:04",
     "channel": 6,  "security": "WPA2", "min_rssi": -70},
    {"ssid": "GuestWifi",    "bssid": "AA:BB:CC:01:02:05",
     "channel": 11, "security": "Open", "min_rssi": -75}
  ]
}
"""

# json.loads() — parses a JSON string into a Python dict
inventory = json.loads(AP_INVENTORY_JSON)

print(f"[Inventory] Site: {inventory['site']}")
print(f"[Inventory] APs configured: {len(inventory['access_points'])}")
for ap in inventory["access_points"]:
    print(f"  {ap['ssid']:20s} Ch{ap['channel']:3d}  {ap['security']:10s}  min RSSI: {ap['min_rssi']} dBm")

# Save the inventory to a file (json.dump vs json.dumps — 'dump' = to file)
inventory_path = Path("ap_inventory.json")
with open(inventory_path, "w") as f:
    json.dump(inventory, f, indent=2)   # indent=2 pretty-prints it
print(f"\n[JSON] Saved inventory to {inventory_path}")
Block 2 — Loading YAML with yaml.safe_load

Always use yaml.safe_load() — never yaml.load(). The unsafe version can execute arbitrary Python code embedded in a YAML file (a security vulnerability). safe_load() restricts parsing to plain data types only.

Python 
# ── Block 2: YAML Test Config ────────────────────────────────

YAML_CONFIG = """
# WLAN Test Suite Configuration
test_name: "Phase 1 Validation"
environment: staging
thresholds:
  min_rssi_dbm: -70
  max_association_time_ms: 3000
  required_security:
    - WPA2
    - WPA3
scan:
  timeout_seconds: 30
  retry_count: 3
  channels_2ghz: [1, 6, 11]
  channels_5ghz: [36, 40, 44, 48]
"""

# yaml.safe_load() — parses YAML string to Python dict/list structure
config = yaml.safe_load(YAML_CONFIG)

print(f"\n[YAML Config] Test: {config['test_name']}")
print(f"  Min RSSI      : {config['thresholds']['min_rssi_dbm']} dBm")
print(f"  Max assoc time: {config['thresholds']['max_association_time_ms']} ms")
print(f"  Required sec  : {config['thresholds']['required_security']}")
print(f"  5 GHz channels: {config['scan']['channels_5ghz']}")

# Save YAML config to file
config_path = Path("test_config.yaml")
config_path.write_text(YAML_CONFIG)
print(f"[YAML] Config saved to {config_path}")
Block 3 — Validating Scan Results Against Config

This is where JSON + YAML combine into real value. Load the expected AP configuration, compare it against a simulated live scan, and report which APs passed or failed their RSSI and security requirements.

Python 
# ── Block 3: Validate scan vs config ─────────────────────────

# Simulated live scan results (what the adapter actually sees)
LIVE_SCAN = [
    {"ssid": "CorpWifi-5G", "bssid": "AA:BB:CC:01:02:03",
     "rssi": -58, "security": "WPA2"},
    {"ssid": "CorpWifi-2G", "bssid": "AA:BB:CC:01:02:04",
     "rssi": -78, "security": "WPA2"},
    # GuestWifi is absent from scan (AP may be down)
]

def validate_scan(inventory, live_scan, min_rssi):
    """
    Compare live scan results against the expected AP inventory.
    Checks: AP presence, RSSI threshold, security type.
    Returns list of (ssid, status, reason) tuples.
    """
    # Build a lookup dict from scan results for O(1) access
    scan_lookup = {ap["ssid"]: ap for ap in live_scan}
    results = []

    for expected_ap in inventory["access_points"]:
        ssid = expected_ap["ssid"]
        found = scan_lookup.get(ssid)

        if not found:
            results.append((ssid, "FAIL", "AP not found in scan"))
            continue

        # Check RSSI threshold
        if found["rssi"] < min_rssi:
            reason = f"RSSI {found['rssi']} dBm below threshold {min_rssi} dBm"
            results.append((ssid, "FAIL", reason))
            continue

        results.append((ssid, "PASS", f"RSSI {found['rssi']} dBm OK"))

    return results

min_rssi = config["thresholds"]["min_rssi_dbm"]
results = validate_scan(inventory, LIVE_SCAN, min_rssi)

print("\n[Validation Results]")
for ssid, status, reason in results:
    icon = "✓" if status == "PASS" else "✗"
    print(f"  [{icon} {status}] {ssid:20s}  {reason}")
