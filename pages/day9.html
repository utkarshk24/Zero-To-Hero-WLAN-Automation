The 'Why' — Conceptual Breakdown

Python Can't Do Everything — But the OS Can

Python is excellent at logic, data manipulation, and reporting. But some things are only exposed via OS-level tools: scanning Wi-Fi, reading interface statistics, setting channels, enabling monitor mode. The subprocess module is Python's bridge to those tools — it spawns a child process, runs any command, captures stdout/stderr, and returns the exit code.

subprocess.run() is the modern, safe way to call external commands.
It replaces the older os.system() (which can't capture output) and subprocess.Popen() (which is more complex than needed for most cases). Use capture_output=True and text=True — you'll use these on almost every subprocess call in this course.

Cross-Platform Wi-Fi Tools

The same Python script needs to work on Linux (where you use iwconfig or nmcli), macOS (where you use airport), and Windows (where you use netsh wlan). A clean command selector function that detects the OS and picks the right command is the foundation of every cross-platform WLAN automation tool.

Block 1 — subprocess.run() Basics

subprocess.run() is a blocking call — Python waits until the command finishes. capture_output=True redirects stdout and stderr into Python string attributes. text=True decodes the bytes to a Python string automatically using the system's default encoding.

Python Day09_subprocess.py 
# =============================================================
# Day 9: subprocess — Running OS commands from Python
# =============================================================

import subprocess
import platform

# ── Block 1: Basic subprocess.run() ─────────────────────────

result = subprocess.run(
    ["ping", "-c", "1", "8.8.8.8"],   # Command as a list (safer than a string)
    capture_output=True,               # Capture stdout + stderr
    text=True,                         # Decode bytes → str automatically
    timeout=10                         # Kill if it hangs > 10 seconds
)

print(f"Return code : {result.returncode}")   # 0 = success, non-zero = failure
print(f"Stdout:\n{result.stdout}")
if result.stderr:
    print(f"Stderr:\n{result.stderr}")
Block 2 — Cross-Platform Command Selector

platform.system() returns "Linux", "Darwin" (macOS), or "Windows". Use this to pick the right Wi-Fi scanning command at runtime. The same Python logic runs everywhere — only the OS command changes.

Python 
# ── Block 2: Cross-platform command selector ─────────────────

def get_wifi_scan_command():
    """
    Return the correct Wi-Fi scan command for this OS.
    Returns a list ready for subprocess.run().
    Raises RuntimeError if the OS is not supported.
    """
    os_name = platform.system()

    if os_name == "Linux":
        # nmcli is more reliable than iwlist on modern Linux
        return ["nmcli", "-t", "-f", "SSID,BSSID,SIGNAL,CHAN,SECURITY",
                "dev", "wifi", "list"]

    elif os_name == "Darwin":  # macOS
        # airport is Apple's built-in Wi-Fi diagnostic tool
        return ["/System/Library/PrivateFrameworks/Apple80211.framework"
                "/Versions/Current/Resources/airport", "-s"]

    elif os_name == "Windows":
        return ["netsh", "wlan", "show", "networks", "mode=bssid"]

    else:
        raise RuntimeError(f"Unsupported OS: {os_name}")

cmd = get_wifi_scan_command()
print(f"\n[OS: {platform.system()}] Scan command: {' '.join(cmd)}")
Block 3 — nmcli Wi-Fi List Parser

Raw command output is just a string. The real automation value comes from parsing that string into structured Python data. On Linux, nmcli -t (terse mode) uses colon-separated fields — easy to split.

Python 
# ── Block 3: nmcli output parser (Linux) ─────────────────────

def nmcli_wifi_list():
    """
    Run nmcli and parse its terse output into a list of AP dicts.
    nmcli -t output format: SSID:BSSID:SIGNAL:CHAN:SECURITY
    """
    result = subprocess.run(
        ["nmcli", "-t", "-f", "SSID,BSSID,SIGNAL,CHAN,SECURITY",
         "dev", "wifi", "list"],
        capture_output=True, text=True, timeout=15
    )

    if result.returncode != 0:
        print(f"[ERROR] nmcli failed: {result.stderr.strip()}")
        return []

    aps = []
    for line in result.stdout.strip().splitlines():
        parts = line.split(":")
        if len(parts) >= 5:
            aps.append({
                "ssid":     parts[0],
                "bssid":    ":".join(parts[1:7]),   # BSSID contains colons itself
                "signal":   int(parts[7]) if parts[7].isdigit() else 0,
                "channel":  int(parts[8]) if parts[8].isdigit() else 0,
                "security": parts[9] if len(parts) > 9 else "Unknown"
            })
    return aps
Block 4 — safe_run() Error Handling Wrapper

In production automation, commands can fail. The adapter might not be in the right mode, a tool might not be installed, or a timeout can occur. A safe_run() wrapper handles all these cases and returns a consistent result object — never crashes your test suite with an unhandled exception.

Python 
# ── Block 4: safe_run() — production error handling ──────────

def safe_run(cmd, timeout=30):
    """
    Run a command safely, catching all possible exceptions.
    Returns: (success: bool, stdout: str, stderr: str, returncode: int)
    """
    try:
        result = subprocess.run(
            cmd, capture_output=True, text=True, timeout=timeout
        )
        return result.returncode == 0, result.stdout, result.stderr, result.returncode

    except subprocess.TimeoutExpired:
        return False, "", f"Command timed out after {timeout}s", -1

    except FileNotFoundError:
        return False, "", f"Command not found: {cmd[0]}", -2

    except PermissionError:
        return False, "", f"Permission denied: try running with sudo", -3

# Example usage
ok, out, err, code = safe_run(["iwconfig"], timeout=5)
if ok:
    print(f"[iwconfig OK] {len(out.splitlines())} lines of output")
else:
    print(f"[iwconfig FAIL] {err}")
